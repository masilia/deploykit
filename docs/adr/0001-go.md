# ADR 0001: Implement deploykit in Go

Status: accepted

## Context
deploykit is orchestration glue: it spawns `ssh`, `rsync`, `docker` and `gpg`, parses env files and YAML, probes HTTP
endpoints and draws a terminal UI. It is I/O-bound, never compute-bound. It must ship as a single static binary for
linux amd64/arm64 and darwin, and for the compose runtime the same binary is copied to the server.

## Decision
Use Go (cobra for commands, Bubble Tea / Lip Gloss / Bubbles / huh for the TUI, yaml.v3, GoReleaser for releases).
Pin a current stable Go release; PLAN.md's earlier floor of 1.23 is a minimum, not a target.

## Consequences
- Cross-compilation and static linking are one config in GoReleaser; goroutines make parallel fleet reads trivial.
- The Charm libraries match the TUI design already specified.
- Go has no sum types: manifest variants are interfaces plus runtime validation, so validation must be strict and tested.

## Alternatives considered
Rust: smaller binaries and sum types, but the workload gains nothing from its speed, cross-compiling to darwin and static
musl needs extra tooling, the YAML ecosystem is less settled (`serde_yaml` was archived in 2024), and the learning curve
is steeper for the team. Reconsider only if the team already knows Rust well.
