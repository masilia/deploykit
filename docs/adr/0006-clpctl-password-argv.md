# ADR 0006: Documented exception to "no secret in a command argument"

Status: accepted

## Context
deploykit's rule is that secrets travel through environment variables or stdin, never as command arguments. But
`clpctl site:add:*` requires `--siteUserPassword`, and `db:add` requires `--databaseUserPassword`. The options we found
documented take no stdin or environment alternative (to be re-checked against the installed `clpctl` version).

## Decision
Accept the exception for these `clpctl` flags only:

- The password is generated by deploykit (random, 24 characters) and never reused.
- The command runs on the server inside a script sent on stdin, so the secret never appears in the local process
  list or in SSH arguments; it is visible only in the server's process list for the duration of the call.
- For site users the password only serves CloudPanel's SFTP and file manager; deploys use the SSH key. It is shown once
  to the operator and not stored.
- Database passwords are written to the target's runtime `.env` on the server (mode 600) and not logged.

## Consequences
- The runner masks these arguments in every log and in `--dry-run` output.
- If a future `clpctl` accepts a file, stdin or environment variable, switch to it and retire this ADR.
